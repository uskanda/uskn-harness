# ADR-0016: 外側のループはハーネスに置かず、リポジトリの規約だけを接点にする

- 状態：採用（2026-11-26）。ADR-0007を置き換える。ADR-0011の決定2の道具から `uskn-loop` を外す
- 決定者：uskanda（change `retire-uskn-loop` のgrilling。2026-11-21の会話と、第1ラウンドのQ1からQ4）
- 関連：ADR-0005、ADR-0007、ADR-0011、ADR-0015、`docs/loop-engineering-2026-09.md`

## 文脈

ADR-0007は、仕様PRを作業指示として受け取るループ `uskn-loop` をハーネスに置いた。
実装したのは段階1（手元から手動で起動する）だけで、`bin/uskn-loop` と `loop/` は約1,400行になった。

その後、issueを起点にセッションを起動し、応答待ちを集める製品switchboardを別に作った。
多くの開発はそちらで進めている。一方で、switchboardの無い端末でも開発する。
ハーネスは、外側のループの無い端末でも単独で働く必要がある。

外側のループの製品は、`claude -p` にユーザー層の設定を読ませない。
そのため、ハーネスのhookとスキルは、外側のループの実行では働かない。
閉じた環境では、`claude -p` の権限モードがdefaultに戻るので、どちらのループも動かない（ADR-0015）。

## 決定

1. `uskn-loop` を廃止する。`bin/uskn-loop`、`loop/`、そのテストを消す。syncは `~/.local/bin/uskn-loop` を作らず、ハーネスの中を指すか、指す先の無い残りを消す。doctorは残りを `warn` で知らせる
2. issueを起点に起動し、新しい文脈でラウンドを繰り返す外側のループは、ハーネスの外の製品に置く
3. ハーネスと外側のループの接点は、リポジトリの規約（`AGENTS.md`、検証規約、`openspec/`）だけにする。ハーネスのスキル、hook、テンプレート、インストーラは、外側のループの製品の名前とAPIを書かない。外側のループの製品も、ハーネスのコマンドを呼ばない
4. 無人の実行でも守らせたい決まりは、ユーザー層ではなく、リポジトリの規約に置く
5. 外側のループの無い端末では、セッションの中の検査で足りるとする。verify gate、`/goal`、`audit` スキルである
6. `spec-pr` を廃止する。`/spec` の出口は `/opsx:apply` だけにする
7. 差分の検査 `uskn-diff-check` を、ハーネスのコマンドにする。`verify` スキルが、完了の報告とPRの前に実行する。verify gateには入れない
8. 実装と別の文脈で判定するスキル `audit` を足す。監査役への指示と判定の形は、`loop/` から移す
9. 決定3の独立は、このADRに書くだけにする。テストでは確かめない

## 検討した代替案

| 案 | 退けた理由 |
|---|---|
| `uskn-loop` を残し、外側のループの無い端末でも無人で回す | 2つのループを保守することになる。外側のループの製品は複数の端末を扱えるので、無人で回したい端末はそちらに足せばよい |
| ハーネスが外側のループの入口（ラベルを付けたissueなど）を作る | 外側のループの無い端末で役に立たない。ハーネスが外側の製品を知ることになる |
| 差分の検査を外側のループだけに置く | 外側のループの無い端末で、消したテストやskipを見つけられない |
| 外側のループが `uskn-diff-check` を呼ぶ | 外側のループが、ハーネスの導入に依存する（Q3） |
| 独立をテストで確かめる | 製品の名前の一覧を保守する費用に見合わない（Q4） |
| `spec-pr` を、仕様をレビューする入口として残す | 作業指示としての役割が無くなった。PRは `pr` スキルで作れる（Q2） |

## 結果

- 良い点：ハーネスから、ループのコードとそのテストが消える。外側のループは、ハーネスの版と関係なく変えられる
- 良い点：外側のループの無い端末でも、差分の検査と監査をセッションの中で使える
- 引き受けるコスト：外側のループの無い端末では、無人でラウンドを繰り返す手段が無い
- 引き受けるコスト：外側のループの製品は、差分の検査と監査を自分で持つ。同じ判断が2か所にある
- 引き受けるコスト：決定3の独立は、テストではなくレビューで守る
- 後回し：verify gateに差分の検査を入れること。Stop hookは、止める以外の形で結果を渡せない。理由を書いて例外を宣言する仕組みも無い
- 後回し：監査役を、道具を読み取りに限ったプラグインのagentとして配ること
- 後回し：`archive-push` が、archiveの前に `audit` を呼ぶこと
- 後回し：外側のループの製品に、監査の段階と差分の検査を足すこと。その製品のリポジトリで扱う
