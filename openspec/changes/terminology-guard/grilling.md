# grilling 記録: terminology-guard

ユーザーの要望は「Claude Codeが一般に知られていない用語を勝手に作り出すことを抑制したい」。
エージェントが先に事例を調査した。対象はClaude Code向けのASD-STE100スタイル、DDDのユビキタス言語スキル2種、AWSの記事、Microsoftスタイルガイド、Valeの語彙機能、textlintとprh。
本リポジトリの地の文も実測した。カタカナ語は異なり132語。バッククォートで書かれた名前は192個。うち24個は、コードとパスのどちらにも存在しなかった。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 用語集の形式と置き場 | 構造化したファイルを正本にする。人が読む表は必要になったら生成する | 第1ラウンド Q1 |
| 用語集のパス | どのリポジトリでも `openspec/glossary.yml`。ハーネス自身も同じ場所に置く。プロダクト側も相対パスとファイル名を揃える | 会話中に確認 |
| 別名の直し方 | prh.ymlの生成はやめ、`terms-check` が用語集を直接読んで別名を指摘する。生成の段取りを増やさないため。汎用の表記ゆれはprh.ymlが引き続き見る | 会話中に確認（Q1の精緻化） |
| 名前の実在検査の厳しさ | hookでは警告、`make verify` では失敗 | 第1ラウンド Q2 |
| 未知語の検査の範囲 | カタカナ語と「」で括った語の両方。一般語リストを持ち、指摘が出た語を足していく | 第1ラウンド Q3 |
| 英語文書への適用 | 同じ規約を`en-writing`と`writing-for-agents`にも書く。名前の実在検査は言語に依らず掛ける | 第1ラウンド Q4 |
| プロダクトリポジトリへの配布 | AGENTS.mdテンプレートに規約の4行を足すだけ。用語集の中身とセンサーの設定は各リポジトリが持つ | 第1ラウンド Q5 |
| 置けるファイルの表現 | 上限という言い方をやめる。規約が求めるファイルだけを置く、が本質。列挙は現時点の内訳にすぎない | 会話中に確認（Q5への補足） |
| 既存プロダクトの一括監査 | スキル `audit-writing` を用意する。最初に用語の洗い出しを行い、用語集を対話で作り、そのあとに一括修正と検証を行う。検証の指摘を順に潰すだけの手順にはしない | 会話中に確認 |

## 後回しにしたもの

- `ubiquitous-language` スキルの導入。会話から用語を抽出する機能は、用語集を1ファイルで手入れする運用と重なる
- 一般語リストの共有。まず本リポジトリの132語で始め、プロダクト側の運用を見てから配布を考える
- 記録（`docs/proposal-2026-09.md` とarchive）への適用。検査対象外のまま
