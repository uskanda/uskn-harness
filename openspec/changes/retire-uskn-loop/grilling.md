# grilling 記録: retire-uskn-loop

2026-11-21の会話で、ユーザーがuskn-loopの廃止とループのハーネス外への移動を提案した。
提案への評価を返し、ユーザーが前提（他端末での開発）を足した。その前提で役割の分け方を示し、ユーザーが `ok` で承認した。
続けて、分け方の細部を第1ラウンドの4問（推奨回答付き）で尋ね、ユーザーが答えた。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| uskn-loopを残すか | 廃止する。ループはハーネスの外で作る。ADR-0007を置き換える | 会話中に確認（ユーザーの提案と、評価への応答） |
| ハーネスと外側のループの依存 | ハーネスは外側のループに依存しない。他の端末でも、外側のループ無しでハーネスだけで開発できる。両者の接点はリポジトリの規約（`AGENTS.md`、検証規約、`openspec/`）だけにする | 会話中に確認（ユーザーが前提として示した） |
| 外側のループの置き場 | issueを起点に起動し、新しい文脈でラウンドを繰り返す外側のループは、ハーネスの外の製品に置く。ユーザーの環境ではswitchboardがこれを担う。外側のループの無い端末では、セッションの中の検査で足りる | 会話中に確認（役割の分け方への `ok`） |
| changeの分け方 | 1つにまとめる。uskn-loopの廃止、差分の検査、監査のスキルを同じchangeで扱う | 第1ラウンドQ1（推奨と違う「1つにまとめる」） |
| `spec-pr` の扱い | 廃止する。スキルとspecを消し、`/spec` の出口は `/opsx:apply` だけにする | 第1ラウンドQ2（推奨と違う「廃止する」） |
| 差分の検査の置き場 | ハーネスのコマンドにする。外側のループは同じ検査を自分で持ち、互いを呼ばない | 第1ラウンドQ3（推奨どおり） |
| 独立の確かめ方 | ADRに書くだけにする。ハーネスの中に外側のループの名前が無いことを確かめるテストは作らない | 第1ラウンドQ4（推奨と違う「ADRに書くだけ」） |

## 後回しにしたもの

- verify gateに差分の検査を入れること。Stop hookは、止める以外の形でエージェントに結果を渡せない。理由を書いて例外を宣言する仕組みも無い。Q3の選択肢の説明はverify gateにも触れていたため、設計でこの判断を書き、PRで確認を求める
- 監査役を、道具を読み取りに限ったプラグインのagentとして配ること。skills-dirプラグインがagentsを読み込むかを確かめてから決める
- `archive-push` がarchiveの前に `audit` を呼ぶこと。費用と、監査を必須にする範囲を別に決める
- switchboard側の変更（監査の段階と差分の検査を足すこと）。switchboardのリポジトリで扱う
