# grilling 記録: ja-writing-baseline

`ja-writing` の文体基準はPhase 3で「暫定」のまま残っていた（`docs/proposal-2026-09.md` §12.9の後回しリスト）。
先立ってエージェントが調査した。textlintの各プリセット、prh、textlint MCP、EARS記法、Diátaxis、日本語の実務例（サイバーエージェント、SmartHR）、Claude公式のスキル作法。
候補のプリセットは既存40文書に当てて指摘数を測ってから提示した。2026-09-05、セッションd69404e3。

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 文体の基準 | 成果物で分ける。仕様、ADR、設計、コミットは常体。pull request 本文、チャット、UI 文言は敬体。検査対象は前者なので `no-mix-dearu-desumasu` の本文設定を「である」にする | 第 1 ラウンド Q1 |
| JTF プリセットの採否 | そのまま追加し、文体を JTF に合わせる。全角と半角の間にスペースを入れない。既存 40 文書の 1970 件は `textlint --fix` で直す | 第 1 ラウンド Q2 |
| スペース規則のセンサー | 不要。JTF の 3.1.1 が同じ範囲を見るため、`preset-ja-spacing` は入れない | 第 1 ラウンド Q3 |
| 表記ゆれの辞書 | prh を入れる。辞書は 10 語程度から始める。実測で見つかった「リポジトリ」と「リポジトリ」の混在を統一する | 第 1 ラウンド Q4 |
| EARS 記法 | 採用する。日本語の要求文テンプレートを `schemas/uskn` の specs 生成指示に置く。要求文の型は文章の型ではなく仕様の型のため。`ja-writing` からは参照だけ張る | 第 1 ラウンド Q5 |
| textlint MCP | 使わない。PostToolUse hook のままにする。hook は決定的に発火するが、MCP はモデルが呼ぶかどうかに依存するため | 第 1 ラウンド Q6 |
| センサー外の文章 | `commit` と `pr` スキルに textlint の手順を組み込む。チャットは対象外と明記する。UI 文言はプロダクトリポジトリ側の設定に委ねる | 第 1 ラウンド Q7 |
| 文体サンプル | `assets/voice/ja/` は空のままにする。文体が確定すれば基準がサンプルの役割を果たす | 第 1 ラウンド Q8 |

## 後回しにしたもの

- `--fix` の自動適用をどこまでhookに持たせるか。今回は手で呼ぶ手順だけを置く
- Diátaxisによる文書の4分類。今のハーネスは文書の種類が少なく、導入の利得が薄い
- 記録（`docs/proposal-2026-09.md` と `openspec/changes/archive/`）の書式は直さない。検査対象外のため、新しい文体との差は残る
- プロダクトリポジトリへのtextlint設定の配布。プロダクト側の `.textlintrc*` 優先という既存の決定のまま
