## Context

`openspec-archive-change` はOpenSpecのCLIが配るスキルで、差分があるとspecの同期を尋ね、未完了の成果物や項目があると続けるかを尋ねる。
`commit` と `push` はこのリポジトリの `skills/git/` にある。`push` は未コミットの変更があると自分で `commit` を呼び、保護ブランチの判定も持つ。
自前のスキルは `skills/` に置けば `uskn-harness sync` が配り、`make verify-skills` がfrontmatterの `name` とディレクトリ名の一致を確かめる。
ユーザーだけが呼べるスキルの前例は `allow-repo` と `ok` で、`ok` は `bin/tests/ok-skill.bats` でfrontmatterを確かめている。

## Goals / Non-Goals

**Goals:**
- 手順は既存のスキルを呼ぶだけにし、`archive-push` の本文には呼ぶ順番と、各スキルの問いへの答えだけを書く
- 止まる場面を、何も動かしていない時点に寄せる

**Non-Goals:**
- 複数の変更をまとめて処理すること（grillingで後回しにした）
- `openspec-archive-change`、`commit`、`push` の振る舞いを変えること

## Decisions

- **置き場は `skills/archive-push/`。** `skills/git/` はgit操作だけのスキルの置き場で、これはOpenSpecの手順が主なので直下に置く。`spec` や `no-grilling` と同じ階層になる
- **順番は、確認と判定、検証、項目の更新、archive、検証、コミット、push。** 尋ねる場面（コミット範囲、迷う項目）と止まる場面（変更を伴う項目、1回目の検証）をすべて、作業ツリーを変える前に置く。こうすると、途中で止まっても元に戻す作業が要らない。例外は2回目の検証の失敗だけで、そのときは残ったものを報告する
- **`openspec-archive-change` は呼び出し、問いへの答えを本文で先に与える。** 同期は「Sync now」、同期済みなら「Archive now」を選ぶ。未完了の成果物や項目の警告は、先の判定で片付けてから呼ぶので出ない。出た場合は判定の漏れなので止まる。手順を写す案は、外部スキルを写さないという制約に反し、CLIの更新にも追従できない
- **コミット範囲は `commit` への指示で絞る。** archive分だけを選んだときは、変更のディレクトリの移動、同期したmain specs、更新した `tasks.md` だけをコミットするよう指示する。要約行も指定する。`commit` は2〜5コミットに分ける既定を持つので、1コミットにするよう明示する
- **未コミットの実装は関係ありとみなす。** `tasks.md` かproposalのImpactに名前のあるファイルは、この変更の実装として扱う。archiveのコミットより前に `commit` で別にコミットする。実装を毎回「無関係」として尋ねると、実装を終えてすぐ使うたび確認が入るからである。そのほかのファイルがあるときだけ範囲を尋ねる
- **pushは `push` を呼ぶ。** コミット済みなので `push` はそのままpushする。保護ブランチなら `push` が自分の規則で判断し、拒否されれば報告して止まる
- **センサーは `bin/tests/archive-push-skill.bats`。** `name: archive-push` と `disable-model-invocation: true` を確かめる。`ok-skill.bats` と同じ形にする
- **本文に実例を3つ載せる。** 未完了の項目が無い普通の流れ、ユーザーの確認の項目を完了とみなす流れ、未実装の項目で止まる流れ

## Risks / Trade-offs

- 未完了の項目の分け方をエージェントが誤り、未実装を完了とみなす → 迷ったら尋ねる規則に加え、完了とみなした項目を報告とarchiveの注記に残し、後から見つけられるようにする
- `openspec-archive-change` の問いの文言がCLIの更新で変わる → 本文には文言でなく意図（同期する、同期済みならarchiveする）で答えを書く
- 2回目の検証が失敗すると、移動と同期が未コミットのまま残る → 残ったファイルを報告で列挙する。実装側の失敗は1回目で止まるため、起きるのは同期の結果による失敗に限られる
- 検証を2回走らせるので時間がかかる → pushまで一括で進む以上、許容する
