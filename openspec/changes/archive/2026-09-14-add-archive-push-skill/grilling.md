# grilling 記録: add-archive-push-skill

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| スキル名 | `archive-push` とする。`/opsx:archive` と `/push` の組み合わせだと名前から読める | 第1ラウンド Q1 |
| archiveの実装方法 | 外部スキル `openspec-archive-change` をSkillツールで呼び、その問いへの既定の答えだけを書く。手順は写さない | 第1ラウンド Q2 |
| specの同期 | 確認を求めずに同期する。同期済みならそのままarchiveする | 第1ラウンド Q3 |
| 未完了の項目があるとき | 未実装や未検討の項目があれば止まる。ユーザーの確認のようにコードの変更を伴わない項目は、完了とみなしてarchiveしてよい | 第1ラウンド Q3（ユーザーが上書き） |
| `make verify` を走らせるか | 走らせる。失敗したらコミットせずに止まる | 第1ラウンド Q4 |
| コミットの範囲 | 始める前に `git status` を見る。無関係な未コミットの変更があれば、archive分だけか全部かを `AskUserQuestion` で尋ねる。無ければ確認せずに進む | 第1ラウンド Q5 |
| コミットメッセージ | `commit` スキルを呼び、要約行を「`<name>`をarchiveし、main specsに反映」に指定する。specが無ければ「`<name>`をarchive」。本文に同期した能力を並べる | 第1ラウンド Q6 |
| 誰が起動できるか | ユーザーの `/archive-push` だけ。frontmatterに `disable-model-invocation: true` を付ける。pushが外に出るため | 第1ラウンド Q7 |
| 一度に扱う変更 | 1回に1つ。名前が無ければ推定し、曖昧なら尋ねる | 第1ラウンド Q8 |
| センサーと文書 | batsでfrontmatterの `name` と `disable-model-invocation` を確かめる。`AGENTS.md`、`templates/user/CLAUDE.md`、`README.md` に1行ずつ足す | 第1ラウンド Q9 |
| 未完了の項目の分け方 | ①コードや文書、specの変更を伴う項目は止まる。②エージェントがコマンドで確かめられる項目はその場で実行し、通れば完了、失敗なら止まる。③ユーザーの確認などエージェントが実行できない項目は完了とみなす | 第2ラウンド Q10 |
| 完了とみなした項目の記録 | archiveの前に `- [x]` にし、行末に「（archive-pushで完了とみなした）」と注記する | 第2ラウンド Q11 |
| 分け方に迷う項目 | `AskUserQuestion` で項目ごとに尋ねる | 第2ラウンド Q12 |
| `make verify` の順序 | archiveの前と後に1回ずつ走らせる。前で失敗したら何も動かさずに止まる。後で失敗したら作業ツリーに残ったものを報告して止まる | 第2ラウンド Q13 |
| 実装のファイルが未コミットのとき | 関係ありとみなす。`tasks.md` やproposalのImpactに名前のあるファイルは、archiveの前に実装として別のコミットにする。それ以外のファイルがあるときだけ範囲を尋ねる | 実装中に会話中で確認（2026-09-14） |
| pushと保護ブランチ | `push` スキルに任せる | 第1ラウンド Q5〜Q6の前提として会話中に確認 |
