# grilling 記録: adapt-for-trellis-host

## 決定

| 決定 | 選択 | 出典 |
|---|---|---|
| 変更の範囲 | 4つすべて。最低線で固めたOSユーザーへの導入、hookの誤検知、`~/repos`以外の開発用checkout、Linux専用の許可。古い機能の整理は別の変更にする | 第1ラウンド Q1 |
| 自律の実行と手動の実行 | 分けて考える。別のリポジトリに分けることもありうる | 第1ラウンド Q1（ユーザーの追加） |
| この端末で使うOSユーザー | 管理者と、エージェントの実行用のOSユーザーの両方 | 第1ラウンド Q2 |
| 分け方の軸 | 設定は実行の環境で、スキルとhookは実行の起点で分ける | 第2ラウンド Q3 |
| OSごとの許可 | 共通の設定断片にOS別の設定断片を重ねる。Linux専用の許可はLinux用へ移す | 第2ラウンド Q4 |
| `terms-check`が読むリポジトリ | 書いたファイルが属するgitルート | 第2ラウンド Q5 |
| 検査から外すファイル | ファイルが属するリポジトリの`.textlintignore`を、textlintと`terms-check`の両方が読む | 第2ラウンド Q6 |
| bash-guardの注意 | 1つのセッションで1回だけ出す。失敗すると分かっている形の拒否は残す | 第2ラウンド Q7 |
| 開発用のcheckoutの場所 | 端末別の設定に書ける。既定は`~/repos/uskn-harness` | 第2ラウンド Q8 |
| 設定の選び方 | 設定断片を「管理者の環境」用と「閉じた環境」用の2つに分ける | 第3ラウンド Q9 |
| 閉じた環境用から外すもの | `sandbox.excludedCommands`、`allowUnsandboxedCommands: true`、`failIfUnavailable: false`、`remoteControlAtStartup`、`defaultMode: auto` | 第3ラウンド Q10 |
| 起点での分割 | 分けない。読み上げ通知と画面向けの道具は、閉じた環境では入れない。スキルは共通 | 第3ラウンド Q11 |
| リポジトリの分割 | いまは分けない。整理の変更のあとに、もう一度判断する | 第3ラウンド Q12 |
| 閉じた環境へのハーネスの置き方 | 管理者が、実行用のOSユーザーの書けないcheckoutを置く。実行用のOSユーザーは`sync --no-pull`で、symlinkと設定だけを自分のホームに置く | 第3ラウンド Q13 |
| 閉じた環境の道具 | 管理者が、ピンどおりの道具を、実行用のOSユーザーの書けない共有の場所に置く | 第4ラウンド Q14 |
| 閉じた環境のsyncを実行する者 | 管理者がcheckoutを更新したあと、端末の土台の導入スクリプトが実行用のOSユーザーとして実行する。ハーネスはコマンドを用意する | 第4ラウンド Q15 |
| 環境の種類の渡し方 | 実行用のOSユーザーの書ける場所には置かない（第5ラウンド Q21で詰めた） | 第4ラウンド Q16 |
| 閉じた環境でsandboxを緩める指定 | syncは端末別設定から持ち込まない。doctorは警告する。`/sandbox-exclude`は止まって理由を出す | 第4ラウンド Q17 |
| hookがsandboxの外でリポジトリのコードを動かす件 | 閉じた環境では、hookがリポジトリのコードを`sandbox-exec`の中で動かす。この変更に入れる | 第5ラウンド Q18（監査で見つけた） |
| hookのPATH | 閉じた環境では、hookはホームの下をPATHに足さない。sandboxで書ける場所からmiseとpnpmを外す | 第5ラウンド Q19 |
| 閉じた環境のgit | セッションはローカルのcommitまで。pushとPRは外側が行う | 第5ラウンド Q20 |
| 環境の種類を実行時に知る手段 | checkoutの側に置く、rootの持ち物の印で判定する。引数は要らない | 第5ラウンド Q21（Q16を直した） |
| 閉じた環境での完了の条件 | 起動スクリプトを通した`claude -p`と対話で、hookとスキルが働くこと。uskn-loopとswitchboardは対象外 | 第5ラウンド Q22 |
| textlintの設定の選び方と除外 | ファイルの側のgitルートで選ぶ。`terms-check`は同じglobの意味を持ち、`make verify`でも読む。どのリポジトリにも属さないファイルは、termsは検査せず、textlintはハーネスの設定で検査する | 第5ラウンド Q23 |
| 閉じた環境の道具とサードパーティのスキル | 共有の場所に置き、linkだけを張る。置き先を指定できるコマンドと、doctorの版の確認を用意する。版はSHAで固定する | 第5ラウンド Q24 |
| 閉じた環境用からさらに外すもの | `WebFetch(domain:*)`、`allowAllUnixSockets`。`/sandbox-allow-host`も断る | 第5ラウンド Q25 |
| 名前とADR | 「管理者の環境」と「閉じた環境」（コードでは`admin`と`confined`）、「OS別の設定断片」。ADRを1つ足す。公開リポジトリなので、端末の土台のOSユーザーの名前は書かない | 第5ラウンド Q26 |
| 開発機の参照点の移行 | 手作業で置き換え、doctorが案内する | 第5ラウンド Q27 |
| 無人の実行での行き止まり | `/add-dir`を前提にした拒否で止まるだけでよい。そう明記する | 第5ラウンド Q28 |
| 閉じた環境の`-p`で書く許可 | 閉じた環境用の`permissions.allow`に`Edit`と`Write`を入れる。足りるかは実機で確かめる | 第6ラウンド Q29（Q22の権限モードを直した） |
| ユーザー層の設定で最低線が緩む件 | 端末の土台の課題として、そちらの別の変更で扱う。ハーネスは閉じた環境用の設定を、書き込まずに出力するオプションを持つ | 第6ラウンド Q30 |

## 後回しにしたもの

- 古い機能の整理（別の変更）
- リポジトリを分けるかの判断（整理の変更のあと）
- 端末の土台の側の呼び出し、共有の置き場の用意、ユーザー層の設定の持ち主（端末の土台の別の変更）
- hookを囲む`sandbox-exec`の規則を、Claude Codeのsandboxと同じ強さにそろえること。この変更では、トークンの置き場を読ませないことと、外への直接の通信を止めることに絞る
