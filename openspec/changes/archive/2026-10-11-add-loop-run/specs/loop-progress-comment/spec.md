## Purpose

ループの状況を、PRかMRの1つのコメントに書き換えながら示す仕組み。通知の数を抑えつつ、今の状態とラウンドごとの結果を1か所で見られるようにする。

## ADDED Requirements

### Requirement: 1つのコメントを書き換える
ループは、PRかMRごとに1つの進捗コメントを持ち、状態が変わるたびにそのコメントを書き換えなければならない（MUST）。
進捗コメントは、見分け用の印 `<!-- uskn-loop -->` を含まなければならない（MUST）。
再開したとき、ループは印を持つ自分のコメントを探して書き換え、新しい進捗コメントを作ってはならない（MUST NOT）。

#### Scenario: ラウンドをまたぐ
- **WHEN** 3ラウンドでループが終わる
- **THEN** PRの進捗コメントは1つだけで、3ラウンド分の結果を持つ

#### Scenario: 再開
- **WHEN** 中断のあとで同じPRに `uskn-loop run` を再実行する
- **THEN** 既存の進捗コメントが書き換えられ、2つ目の進捗コメントは作られない

### Requirement: 進捗コメントの中身
進捗コメントは日本語で書き、次を持たなければならない（MUST）。

- 先頭の状態：実装中、検証中、監査中、完了、停止のどれか
- 対象のchangeの名前
- ラウンドごとの表：検証の結果、修正必須の指摘の件数、費用の見積もり、所要時間
- 費用の見積もりの合計
- 最新の指摘：折りたたんで示す

#### Scenario: 監査中の表示
- **WHEN** 2ラウンド目の監査役が動いている
- **THEN** 進捗コメントの先頭は監査中で、表には1ラウンド目の行と2ラウンド目の途中の行がある

### Requirement: 生の出力を載せない
ループは、コマンドやツールの生の出力を進捗コメントに載せてはならない（MUST NOT）。
生の出力は状態ディレクトリのログに残し、進捗コメントには要約と場所だけを書く。

#### Scenario: 検証の失敗
- **WHEN** 検証規約が失敗する
- **THEN** 進捗コメントには失敗した検査の名前が書かれ、出力の全文はローカルのログにだけある

### Requirement: 完了時のコメント
完了基準を満たしたとき、ループは進捗コメントとは別に、結果のコメントを新しく書かなければならない（MUST）。
結果のコメントは、ラウンドの数、費用の見積もりの合計、推奨の指摘、次の操作（確認、PRのブランチでの `/archive-push`、マージ）を持つ。

#### Scenario: 完了の通知
- **WHEN** ループが完了する
- **THEN** PRに新しいコメントが1つ増え、その中に `/archive-push` の案内がある

### Requirement: 停止時のコメント
停止条件に当たったとき、ループは進捗コメントとは別に、停止のコメントを新しく書かなければならない（MUST）。
停止のコメントは、当たった停止条件、監査役の問い（あれば）、残っている修正必須の指摘、再開のコマンドを持つ。

#### Scenario: 人の判断待ち
- **WHEN** 監査役が「期限切れのトークンを401と403のどちらで返すか」という問いを返して止まる
- **THEN** 停止のコメントにその問いがそのまま書かれ、再開のコマンドとして `uskn-loop run 12` が示される
